# t-report

Прототип системы еженедельной отчётности на основе Excel-источника.

Проект автоматически проходит полный пайплайн обработки данных: читает исходный Excel-файл, проверяет структуру обязательных листов, нормализует строки, выполняет аналитическую обработку записей и собирает итоговый отчёт.

Текущая версия ориентирована на локальный запуск и демонстрацию рабочего сквозного контура: **от входного `.xlsx` до preview-отчёта, email-пакета и SMTP-отправки**.

---

## Назначение проекта

Система предназначена для автоматизированной сборки еженедельного отчёта по двум наборам данных из Excel:

- записи по КП;
- записи по поставкам.

Проект не сводится к одному большому скрипту: обработка разбита на отдельные этапы, чтобы код было проще развивать, проверять и поддерживать.

---

## Что делает система

Текущая реализация выполняет следующие шаги:

1. читает Excel-файл;
2. ищет обязательные листы;
3. валидирует структуру заголовков;
4. нормализует строки и значения ячеек;
5. выделяет записи по заданным правилам;
6. сортирует результаты;
7. формирует итоговый preview-отчёт;
8. собирает email-пакет (`txt + docx + xlsx`);
9. умеет отправлять пакет по email через SMTP;
10. формирует управленческую сводку по каждому менеджеру;
11. показывает косвенные узкие места по производителям и филиалам;
12. собирает DOCX с заголовками Times New Roman чёрного цвета.

---

## Архитектурная идея

Проект построен как последовательный пайплайн обработки:

**источник данных → проверка структуры → нормализация → анализ → сортировка → сборка отчёта → упаковка → доставка**

Такой подход позволяет:
- отделять ответственность модулей;
- локализовать ошибки по этапам;
- дорабатывать систему постепенно;
- использовать один и тот же каркас для дальнейшего расширения.

## Структура проекта

- `report_tool.py` — основная точка входа
- `preview_orchestrator.py` — координация preview-сценария
- `cli_parser.py` — разбор аргументов командной строки
- `report_context_factory.py` — подготовка даты отчёта и временного контекста
- `weekly_report_pipeline.py` — единый сборщик доменной модели отчёта
- `email_package_orchestrator.py` — сборка email-пакета
- `email_sender.py` — SMTP-отправка письма с вложениями
- `send_email_orchestrator.py` — координация send-сценария
- `management_insights.py` — управленческая аналитика по менеджерам и узким местам
- `exel_sourse_reader.py` — чтение Excel-файла и обязательных листов
- `structure_validator.py` — проверка структуры и заголовков
- `kp_normalizer.py` — нормализация строк по КП
- `delivery_normalizer.py` — нормализация строк по поставкам
- `entity_mapper.py` — преобразование нормализованных записей в рабочие сущности
- `kp_analyzer.py` — анализ записей по КП
- `delivery_analyzer.py` — анализ записей по поставкам
- `result_sorter.py` — сортировка итоговых результатов
- `report_builder.py` — сборка итогового текстового отчёта
- `console_output.py` — вывод результата в консоль

## Требования

- Python 3.14+
- локальный Excel-файл с ожидаемой структурой листов
- пакеты `openpyxl` и `python-docx`

Установка зависимостей:

```powershell
py -m pip install openpyxl python-docx python-dotenv
```

Для удобной локальной конфигурации можно создать `.env` в корне проекта. `report_tool.py` загрузит его автоматически.

---

## Быстрый запуск

Из корня проекта:

```powershell
py .\report_tool.py --preview --date 2026-03-30
```

Собрать локальный email-пакет:

```powershell
py .\report_tool.py --build-email-package --date 2026-03-30 --output-dir .\output
```

Отправить email:

```powershell
py .\report_tool.py --send --date 2026-03-30 --email-to analyst@example.com --output-dir .\output
```

---

## SMTP-конфигурация

Для режима `--send` нужны переменные окружения:

- `T_REPORT_SMTP_HOST` — SMTP-сервер
- `T_REPORT_SMTP_PORT` — SMTP-порт, по умолчанию `587`
- `T_REPORT_SMTP_USERNAME` — логин
- `T_REPORT_SMTP_PASSWORD` — пароль
- `T_REPORT_EMAIL_FROM` — адрес отправителя; если не указан, берётся `T_REPORT_SMTP_USERNAME`
- `T_REPORT_EMAIL_TO` — получатели через запятую; используется, если не передан `--email-to`
- `T_REPORT_SMTP_SECURITY` — режим защиты: `starttls`, `ssl` или `none`

Пример для PowerShell на один сеанс:

```powershell
$env:T_REPORT_SMTP_HOST = "smtp.gmail.com"
$env:T_REPORT_SMTP_PORT = "587"
$env:T_REPORT_SMTP_USERNAME = "your_mail@gmail.com"
$env:T_REPORT_SMTP_PASSWORD = "app_password_here"
$env:T_REPORT_EMAIL_FROM = "your_mail@gmail.com"
$env:T_REPORT_EMAIL_TO = "boss@example.com,team@example.com"
$env:T_REPORT_SMTP_SECURITY = "starttls"
```

После этого можно запускать:

```powershell
py .\report_tool.py --send --date 2026-03-30 --output-dir .\output
```

---

## Что отправляется в режиме `--send`

Письмо включает:

- тему, собранную из даты отчёта;
- текст письма с ключевыми показателями и наблюдениями;
- вложение `DOCX` с краткой сводкой;
- вложение `XLSX` с детальной выгрузкой.

Локальные копии файлов сохраняются в указанную папку `output`.


---

## Что изменено в текущей итерации

Новая версия отчёта добавляет:

- сводку по каждому менеджеру с индексом нагрузки и оценкой эффективности;
- объяснение, почему менеджер успевает или не успевает, на основе backlog по КП и ближайшей нагрузки по поставкам;
- косвенные узкие места по производителям и филиалам;
- новые листы в XLSX: `Менеджеры`, `Узкие места — производители`, `Узкие места — филиалы`;
- обновлённый DOCX со стандартными чёрными заголовками Times New Roman.
